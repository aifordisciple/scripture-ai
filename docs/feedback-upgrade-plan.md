# 用户反馈系统升级计划

## 一、总体目标

构建一个完善的用户反馈管理系统，实现：
1. 用户：便捷提交、实时追踪、及时响应
2. 管理员：高效处理、智能分配、数据驱动

## 二、升级阶段

### Phase 1: 核心体验优化（优先级：高，预计 3 天）

#### 1.1 用户端优化
- [ ] **搜索功能**：用户可搜索历史反馈（按标题、内容）
- [ ] **状态筛选**：用户可按状态筛选反馈列表
- [ ] **刷新按钮**：手动刷新反馈列表
- [ ] **已解决提示**：已解决的反馈显示"已关闭"状态，回复框改为"感谢您的反馈"提示

#### 1.2 管理员端优化
- [ ] **搜索功能**：搜索用户名、邮箱、标题、内容
- [ ] **快捷回复模板**：预设常用回复模板
  - "感谢您的反馈，我们已收到并正在处理中..."
  - "该问题已在最新版本修复..."
  - "您的建议非常有价值，我们已记录..."
- [ ] **批量操作**：批量标记状态、批量删除

### Phase 2: 通知增强（优先级：高，预计 2 天）

#### 2.1 邮件通知
- [ ] 关键节点邮件通知
  - 用户：收到管理员回复
  - 管理员：新反馈提交
- [ ] 邮件模板设计
- [ ] 用户可选择关闭邮件通知

#### 2.2 实时通知优化
- [ ] WebSocket 实时推送（利用现有 use-realtime.ts）
- [ ] 浏览器推送通知（Notification API）
- [ ] 通知声音提醒（可配置）

### Phase 3: 高级管理功能（优先级：中，预计 4 天）

#### 3.1 数据模型升级
```prisma
model Feedback {
  // ... 现有字段
  priority    Priority      @default(NORMAL)  // 新增：优先级
  assignedTo  String?       // 新增：分配给特定管理员
  assignee    User?         @relation(fields: [assignedTo], references: [id])
  tags        String?       // 新增：标签（JSON 数组）
  firstResponseAt DateTime? // 新增：首次响应时间
  resolvedAt  DateTime?     // 新增：解决时间
  slaHours    Int?          // 新增：SLA 时限（小时）
}

enum Priority {
  LOW
  NORMAL
  HIGH
  URGENT
}
```

#### 3.2 管理员功能升级
- [ ] **优先级标记**：紧急/高/普通/低
- [ ] **任务分配**：指派给特定管理员
- [ ] **标签管理**：自定义标签分类
- [ ] **SLA 监控**：超时预警
- [ ] **数据看板**：
  - 平均响应时间
  - 解决率趋势
  - 类型分布图
  - 用户满意度（可选）

### Phase 4: 自助服务（优先级：中，预计 2 天）

#### 4.1 常见问题 FAQ
- [ ] FAQ 入口：提交反馈前展示常见问题
- [ ] FAQ 管理：管理员可增删改查
- [ ] 智能推荐：根据反馈内容推荐相关 FAQ

#### 4.2 反馈引导
- [ ] 提交前检查清单
- [ ] Bug 报告模板（步骤、预期、实际）
- [ ] 功能建议模板（场景、需求、价值）

### Phase 5: 数据分析（优先级：低，预计 2 天）

#### 5.1 统计报表
- [ ] 反馈趋势图
- [ ] 类型占比图
- [ ] 响应时间分析
- [ ] 用户活跃度分析

#### 5.2 导出功能
- [ ] 导出为 CSV/Excel
- [ ] 自定义时间范围
- [ ] 自定义字段选择

## 三、技术实现方案

### 3.1 邮件通知
```
使用现有 nodemailer 或集成第三方服务（SendGrid/阿里云邮件推送）
配置环境变量：
- SMTP_HOST
- SMTP_PORT
- SMTP_USER
- SMTP_PASS
```

### 3.2 实时推送
```
复用现有 hooks/use-realtime.ts
或集成 Server-Sent Events (SSE)
```

### 3.3 搜索功能
```
前端：添加搜索框，防抖输入
API：支持 search 参数，模糊查询 title + content
```

### 3.4 批量操作
```
API：新增 POST /api/feedback/batch
Body：{ action: 'update_status' | 'delete', ids: string[], data?: any }
```

## 五、风险与注意事项

1. **邮件发送频率**：需配置发送频率限制，防止被标记为垃圾邮件
2. **敏感信息**：反馈内容可能包含敏感信息，需考虑脱敏
3. **性能优化**：大量反馈时，列表查询需要优化索引
4. **权限控制**：确保管理员权限校验严谨
